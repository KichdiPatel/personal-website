# Papermarket

I kept wanting to test Polymarket trading ideas without risking real money every time I changed a bot. Backtests are helpful, but I really wanted to forward test without building custom paper trading logic into every bot. Polymarket had a staging API URL, but I saw in their Discord that it wasn't going to be functional for the public. So I built Papermarket.

Basically, you create a paper trading account, change the API base URL in your Polymarket client to Papermarket, and start forward testing with simulated funds. When you're ready to trade live, you switch the URL back to Polymarket. I also built a dashboard if you wanted to place paper trades through a UI.

I built the API with FastAPI and Postgres. It handles accounts, API keys, orders, and trades, with endpoints shaped around Polymarket's CLOB API. I also built a separate fill engine that watches the order book for markets with open paper orders. When the best bid or ask crosses your price, it records a simulated trade.

I really enjoyed the challenge of trying to recreate Polymarket's API. It wasn't just about matching the request and response schemas. Market orders, limit orders, and fills all needed to behave the way a Polymarket client expected. Building the fill engine was a lot of the work, but it was also the most interesting part for me.
